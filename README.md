# supplier-doc-automation

> **供应商文档自动化流水线** —— 邮件驱动的 B2B 文档协同：AI 邮箱收件 → 协同表格确认 → Word 协议生成 → 自动回发，全程无人值守。
>
> ⚠️ **脱敏声明**：本仓库为公开演示版。原项目服务于某制造业企业的供应链文档协同场景，出于保密考虑，所有公司名、人名、地址、部门名、编号格式均为占位符（示例甲公司 / 供应商A公司 / 张三 / 平台A 等），真实业务数据（明细表、标准文档、协议、联系人表）均不入库。业务背景已模糊化为通用的"供应商文档协同"场景。

## 项目概述

自动化生成供应商质量保证协议（Word 文档）。**从 AI-Agent 邮箱接收邮件开始** → 提取附件（物料明细表 + 质量标准） → 解析数据 → 生成协议 → **通过 AI-Agent 邮箱发送给业务负责人**。

核心价值：将原本需要数小时的人工填写、校对工作，缩短到几分钟内一键完成。支持单物料和多物料（16 个）批处理。

### 完整数据流（7步）

```
① AI-Agent邮箱收件
    ↓ 解析附件
② 整理信息到钉钉AI表格（状态：待确认供应商）
    ↓
③ 发送钉钉群卡片通知
    ↓ 人工确认供应商
④ 填写供应商名称到钉钉AI表格（状态：已确认供应商）
    ↓ Agent轮询检测
⑤ Agent读取钉钉AI表格 → 获取供应商名称/平台
    ↓
⑥ 生成质量保证协议 + 验证
    ↓
⑦ 通过AI-Agent邮箱发送给平台负责人
    → 更新钉钉AI表格（状态：协议已发送）
    → 发送群通知
```

### 邮件触发格式

| 字段 | 格式 |
|------|------|
| **邮件主题** | `【企业质量协议签订】-{平台}-{申请人}-{N个物料}` |
| **附件1** | `新增原辅料明细.docx` |
| **附件2** | `质量标准.zip` 或 `质量标准.rar`（含多份标准） |

### 关键设计原则

1. **统一数据目录**：邮件接收的附件和生成的协议文件都放在 `data/` 下
2. **按供应商建文件夹**：每个供应商独立目录，方便追溯
3. **版本化管理**：增量更新时创建新版本（v1→v2→v3），不覆盖旧文件
4. **history.json**：记录每次变更的物料列表、版本号、时间戳

## 模板与占位符

模板文件：质量保证协议模板.docx。文档中包含以下占位符：

| 占位符 | 含义 | 数据来源 |
|--------|------|---------|
| {1} | 供应商名称 | 传入参数（从钉钉AI表格获取） |
| {2} | 审核人（甲方联系人） | 钉钉AI表格"甲方联系人"确认；未填时按平台从 平台联系人的对应关系.xlsx 查询 |
| {3} | 联系电话（甲方） | 同上 |
| {4} | 电子邮件（甲方） | 同上 |
| {5} | 签订日期 | 系统自动生成当天日期 |
| {6} | OA流水号 | 传入参数（从OA流程抓取） |

> 甲方信息：默认填写"示例甲公司"及地址"YY省YY市YY区YY路16号"
> 平台C平台：自动切换为"示例丙公司"，地址"XX省XX市XX区XX路1006号"
> 第4步人工在钉钉AI表格确认"甲方公司"后以其为准（含示例丙公司→示例丙公司，其他→示例甲公司）；"甲方联系人"决定审核人/电话/邮箱。
> 乙方信息：仅填写供应商名称，联系方式留空

## 数据文件说明

### 1. 新增原辅料明细.docx

某产品（占位描述） 的新增原辅料信息。包含若干物料的：
- 物料编码（存货编码，如 9000000001，**必须是 10-12 位数字**，非 6/4 位格式）
- 物料名称 / 物料中文名称
- 规格/浓度
- 货号/克隆号或CAS号（=质量标准表中的货号列，如 DEMO-0001）
- 品牌/产地、储存条件/保质期、物料属性等

### 2. 企业质量标准文件

每个物料独立一份质量标准文档，解析其中的：
- 1.质量指标 → 检验项目 + 标准值
- 2.检验方法 → 测试方法
- 如无对应检验方法则填 /

`email-database/QA/` 下目前共 **16 份 `*原料企业质量标准.docx` + 16 份 `企业质量标准-{平台}-{申请人}-*.docx`**，**无 0 字节文件**（此前 RAR5 解压导致的 0 字节问题已修复）。

### 3. 平台联系人的对应关系.xlsx

| 平台 | 说明 |
|------|------|
| 各业务平台/平台C | 审核人、电话、邮箱为**内部信息，不随仓库分发**；请在本地维护 `agreement-automation/平台联系人的对应关系.xlsx` |

### 4. 映射文件（data/ 下）

- `_party_c_std_map.json`：示例丙公司物料编码 → 质量标准文件映射
- `_supplier_mapping.json`：供应商名称归一化映射

## 生成文档特点

### 页面布局
- 前 2 页：合同正文（纵向）
- 第 3 页：附件表格（横向，含表1 原辅料明细 + 表2 产品质量标准）

### 表1：原辅料明细（14列）
序号 | 物料编码 | 物料名称 | 物料中文名称 | 规格/浓度 | 主计量单位 | 货号/克隆号或CAS号 | 品牌/产地 | 是否危化品 | 物料属性 | 储存条件 | 保质期 | 开瓶次数 | 冻融次数

### 表2：产品质量标准（8列）
物料编码 | 货号 | 中/英文品名 | 规格 | 检验项目 | 标准值 | 测试方法 | 备注

- 物料编码：与原辅料明细表中的物料编码保持一致（如 9000000001）
- 货号：从原辅料明细表"货号/克隆号或CAS号"列提取（如 DEMO-0001）
- 货号/品名/规格 垂直合并（真实 XML vMerge）
- 货号无值时填"/"，不回退物料编码
- 物料名称从钉钉AI表格获取（docx 可能为"/"保密）
- 备注栏默认填"/"
- 文件名括号统一为中文括号后再匹配
- 无质量标准的物料显示 "/" + "（暂无质量标准）"

### 签章行（7列 grid：甲方 2.5/7 | 乙方 2.5/7 | 日期 2/7）
| 甲方：示例甲公司 | 乙方：供应商名称 | 日期： 年 月 日 |
| （盖章） | （盖章） | |

### 字体规范
- 中文：微软雅黑 / 英文：Times New Roman
- 表头：10.5pt 加粗居中
- 数据：9pt，短文本居中 / 长文本左对齐
- 注释行：8.5pt

## 技术实现

### 核心脚本

| 脚本 | 功能 | 输入 | 输出 |
|------|------|------|------|
| generate_qa_agreement_v3.py | 单物料生成 | 模板 + 1份明细 + 1份标准 | 1份协议 |
| batch_generate_v3.py | 多物料批处理 | 模板 + 1份明细 + N份标准 | 1份汇总协议 |
| qa_email_monitor_main.py | 邮件监控 | AI-Agent 邮箱 | 附件下载 + 写钉钉表格 |
| qa_confirm_monitor.py | 确认监控 | 钉钉AI表格状态 | 生成协议 + 写 email_tasks |
| send_email_tasks.py | 邮件发送 | email_tasks/ | 发送协议给平台负责人 |

### 核心技术

1. 动态重绘表格（v3架构）
   - 删除模板中的旧表格 → 用 doc.add_table() 创建新表格 → 替换到模板
   - 不再使用 add_row() 修改旧表，避免 XML 结构污染

2. 真实 XML 垂直合并
   - 起始行：`<w:vMerge w:val="restart"/>`
   - 后续行：`<w:vMerge w:val="continue"/>` + 清空段落文本

3. 平台感知
   - 平台 = 平台C → 甲方名称/地址自动切换
   - 联系人/电话/邮箱从 Excel 自动查询

4. 签名行：7列 grid 布局

## 常见问题

### 质量标准文件0字节
早期部分质量标准文件因 RAR5 格式解压兼容性问题为 0 字节。当前 `email-database/QA/` 下已无 0 字节文件；若再次出现，以管理员身份运行 7-Zip 重新解压：
```
"C:\Program Files\7-Zip\7z.exe" x ".\email-database\QA\质量标准+新增原辅料明细表.rar" -o".\email-database\QA\" -y
```

### 垂直合并不生效
python-docx 读取时所有 vMerge 都显示为 restart，但 Word 打开时渲染正确。原始 XML 已验证正确。

### 货号显示为存货编码
检查 batch_generate_v3.py 中 huohao_map 是否从原辅料明细"货号/克隆号或CAS号"列正确提取。

### 质量标准引用与章节叫法
- "应符合1.X的要求 / 符合1.X的要求"会替换为该小节正文后再填入表2。
- 章节叫法等价：第1章"企业标准"≡"质量指标"，第2章"检验步骤"≡"检验方法"；解析/检索按章节编号，与标题无关。

## 🔄 增量更新机制

### 应用场景

同一供应商分多批新增物料时，系统支持增量合并：

| 批次 | 动作 | 物料数 | 版本 |
|------|------|--------|------|
| 第一批 | 供应商A公司首次提交 | 16个 | v1 |
| 第二批 | 该公司新增2个物料 | 16+2=18个 | v2 |
| 第三批 | 该公司再新增3个物料 | 18+3=21个 | v3 |

### 增量逻辑

```
1. 收到新邮件 → 解析供应商名称
2. 检查 data/{供应商}/history.json 是否存在历史记录
3. 如果存在：
   a. 读取历史物料编码列表
   b. 解析新附件的物料
   c. 去重合并（排除已存在的历史物料）
   d. 生成完整协议（包含所有历史+新增物料）
   e. 版本号 +1
4. 如果不存在（全新供应商）：
   a. 直接生成协议 v1
   b. 创建 history.json
```

### 增量更新流程

```
【企业质量协议签订】-平台D-张三-2个物料（新增）
  ↓
检查 data/供应商A公司/ 是否存在
  ↓ 存在（已有 v1，16个物料）
读取 history.json → 已有物料编码列表
  ↓
解析新增的2份标准 → 合并为18个物料
  ↓
生成协议 v2 → data/北京供应商A/agreements/QA-DOC-xxx-【生物】-供应商A公司.docx
  ↓
更新 history.json → version=2, material_count=18
```

## 🔄 物料升版

适用于**已存在物料的变更**（标准升版 / 信息升版 / 混合升版），流程：

```
邮件主题/附件含"升版"
  ↓ 写入钉钉表：变更类型 + 升版原因
人工确认供应商/甲方 → 状态：已确认供应商
  ↓ Agent轮询
读取主数据 data/_material_master.json
  ├─ 标准变更：新标准文件 hash 与主数据比对 → std_version+1 → 指标 diff（新增/删除/修改）
  └─ 信息变更：从钉钉表"物料信息补充"或主数据获取最新物料信息
  ↓ 完整性门禁
缺失（名称/规格/货号/品牌/储存条件/标准）→ 回写"待补全字段" → 人工补全 → 下一轮重试
  ↓ 完整
生成供应商全量协议 v+1 → history 记录 change_type/change_summaries → 发送 → 回写"协议已发送"
```

主数据回填：

```
python scripts/build_material_master.py
```

输出 `data/_material_master.json`（编码唯一键）和 `data/_master_missing_report.json`（缺失清单）。

## 🔄 第⑧阶段：供应商回签/回传

协议发送后，供应商填写乙方信息（联系人/电话/邮箱）回传：

```
回传邮件（主题/附件含"回传/回签/盖章/已盖章/乙方信息"）
  ↓ 邮件监控识别
归档 data/{甲方公司}/{供应商}/returned/ → 提取乙方信息（公司名称/住所/联系人/电话/邮箱）→ supplier_info.json
  ↓ 内容级防篡改比对（与生成时的 content_lines 快照）
一致 → 状态"已归档闭环"
不一致 → 状态"待人工复核" + 差异清单 + 群通知
  ↓
后续生成协议时自动回填乙方信息（含签订日期，与甲方一致）到协议第二页【乙方】区域，不再要求供应商重复填写
```

- OA 流水号：生成时先用临时号；确认监控轮询会自动检测钉钉"OA审批流水号"变化并刷新文件名+页眉+history（也可手动运行 `python scripts/refresh_oa_serial.py --supplier <供应商> --serial <OA号>`）。
